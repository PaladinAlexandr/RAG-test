# Простой RAG-сервис: .NET 8 + Ollama

Сервис читает свою базу знаний, разбивает документы на фрагменты, находит их по смыслу и передаёт подходящие фрагменты в `qwen3:8b`. Ответ содержит текст и использованные источники. Индекс хранится в `ConsoleApp6/data/index.json`, поиск выполняется в памяти. Отдельная БД и сторонние NuGet-пакеты не нужны.

## Быстрый запуск

Нужны .NET SDK 8 или новее и установленная Ollama.

1. Запустите Ollama и скачайте две модели:

   ```powershell
   ollama pull qwen3:8b
   ollama pull qwen3-embedding:0.6b
   ```

   Если Ollama ещё не запущена, выполните `ollama serve` в отдельном терминале. Если она уже работает, второй сервер запускать не нужно.

2. В терминале из папки решения:

   ```powershell
   cd C:\Users\admin\source\repos\ConsoleApp6
   dotnet run --project .\ConsoleApp6
   ```

   Адрес API: `http://localhost:5080`. В Visual Studio достаточно открыть решение и запустить проект.

3. Положите свои `.txt` и `.md` в `ConsoleApp6/knowledge`, включая подпапки. Кодировка — UTF-8. Удалите демонстрационный `example.md`, если он не нужен. Затем в другом терминале:

   ```powershell
   Invoke-RestMethod http://localhost:5080/api/reindex -Method Post
   ```

4. Задайте вопрос:

   ```powershell
   $body = @{ question = 'Как сбросить пароль?'; topK = 4 } | ConvertTo-Json
   $result = Invoke-RestMethod http://localhost:5080/api/ask -Method Post `
       -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
   $result.answer
   $result.sources | Format-Table id, document, chunk, score
   ```

## Добавить документ через API

Вместо папки можно отправить текст документа:

```powershell
$body = @{
    name = 'правила.md'
    text = 'Техническая поддержка работает с 09:00 до 18:00. Пароль сбрасывается через кнопку «Забыли пароль».'
} | ConvertTo-Json
Invoke-RestMethod http://localhost:5080/api/documents -Method Post `
    -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

Повторный запрос с таким же именем заменяет прежние фрагменты. Документ сразу доступен для вопросов и сохраняется в JSON-индексе; отдельный файл в `knowledge` не создаётся.

**`POST /api/reindex` полностью заменяет индекс содержимым папки `knowledge`. Документы, добавленные только через API, при этом удаляются из индекса.** Для постоянной базы, которую нужно пересобирать, храните исходные документы в папке.

## API

| Метод и путь | Назначение |
|---|---|
| `GET /api/status` | Документы, число фрагментов, модели, пути и `needsReindex` |
| `POST /api/reindex` | Полная пересборка из папки; тело запроса не требуется |
| `POST /api/documents` | JSON `{ "name": "guide.md", "text": "..." }` |
| `POST /api/ask` | JSON `{ "question": "...", "topK": 4 }`; `topK` необязателен |

Ответ `/api/ask`:

```json
{
  "answer": "Сбросьте пароль через кнопку «Забыли пароль». [1]",
  "sources": [
    { "id": 1, "document": "guide.md", "chunk": 1, "score": 0.82, "text": "..." }
  ]
}
```

`sources` — переданные модели фрагменты, а не независимая проверка её утверждений. Если база пустая или подходящих фрагментов нет, сервис сообщает об этом без вызова чат-модели.

## Настройки

Измените `ConsoleApp6/appsettings.json`:

- `OllamaUrl`: адрес Ollama; по умолчанию `http://localhost:11434`.
- `ChatModel`: `qwen3:8b` для ответов.
- `EmbeddingModel`: `qwen3-embedding:0.6b` для семантического поиска. Это отдельная модель; она нужна и для документов, и для вопросов.
- `KnowledgeDirectory` и `IndexPath`: пути относительно папки проекта либо абсолютные пути.
- `ChunkSize`: размер фрагмента в символах, по умолчанию 1200.
- `ChunkOverlap`: перекрытие соседних фрагментов, по умолчанию 200.
- `TopK`: число фрагментов для ответа, от 1 до 8.
- `MinSimilarity`: минимальное косинусное сходство, по умолчанию 0.3. Подберите по своим документам: это не вероятность правильного ответа.
- `TimeoutSeconds`: время ожидания одного HTTP-запроса к Ollama, по умолчанию 300 секунд.
- `Urls`: адрес самого сервиса, по умолчанию `http://localhost:5080`.

После изменения модели embeddings или размера/перекрытия фрагментов перезапустите сервис и вызовите `/api/reindex`. При изменении содержимого модели под тем же тегом также пересоберите индекс.

## Ограничения и ошибки

Это локальный сервис для небольшой базы: весь индекс находится в памяти, поиск перебирает все векторы. Запускайте один экземпляр сервиса на один файл индекса. Поддерживаются только текст и Markdown; PDF/DOCX сначала преобразуйте в текст. Один документ — до 2 МБ, вопрос — до 2000 символов. Истории диалога нет: каждый вопрос независим.

При ошибке Ollama во время обновления старый индекс сохраняется. Пересборка может занять время: рассчитываются embeddings всех фрагментов.

- `400`: некорректные данные запроса.
- `409`: индекс не соответствует настройкам или изменился размер embeddings; выполните `/api/reindex`.
- `502`: Ollama недоступна, модель не скачана или получен некорректный ответ. Проверьте `ollama list` и `OllamaUrl`.
- `504`: превышено время ожидания Ollama.

По умолчанию API слушает только localhost. Авторизации нет; для публикации в сети потребуются аутентификация и ограничения доступа. Документы отправляются на настроенный адрес Ollama.

## Как устроен код

- `Program.cs`: четыре маршрута API и обработка ошибок.
- `RagService.cs`: разбиение текста, JSON-индекс, поиск по косинусному сходству и формирование контекста.
- `OllamaClient.cs`: запросы к Ollama без SDK-обёрток.
- `RagOptions.cs`: настройки и их проверка.

Используются официальные [Ollama /api/embed](https://docs.ollama.com/api/embed) и [Ollama /api/chat](https://docs.ollama.com/api/chat). Модель поиска: [Qwen3 Embedding](https://ollama.com/library/qwen3-embedding).
